# Prometheus

Personal Telegram chief-of-staff bot. Single user (Yash). All times IST. Built in Python.

## What works

- **`/start`** — registers your Telegram user, captures your name on first contact.
- **Reminder creation**
  - `/r 09:30 weekdays Check LinkedIn perf` (recurring)
  - `/r 21:30 once Buy milk` (one-off, today/tomorrow at HH:MM)
  - `/r in 30 min Quick call` (relative one-off)
  - **Plain English** — "remind me at 9:30 every weekday to check LinkedIn perf" (Gemini-parsed)
- **Fire flow** — at fire time, you get a message with `Done / Cancel / Snooze 30 / Add Note` buttons.
- **Nag loop** — every 10 min if no acknowledgment. First two nags edit the same message; the third sends a fresh escalated one. Cap of 3 nags. Pending fires roll to `missed` at midnight.
- **Snooze** — closes the current fire, schedules a new one in 30 min. Cap of 3 snoozes; after that the Snooze button hides.
- **Add Note** — bot asks "Shoot.", captures your next text, then offers `Done / Pending`.
- **`/list`** / **`/kill <id>`** / **`/pause <id>`** / **`/resume <id>`** — manage active reminders.
- **Daily rhythm**
  - `00:00 IST` — recap with sleep buttons. Pending fires get swept to missed.
  - `01:00 IST` — re-prompt sleep if you said "still up".
  - `10:30 IST` — morning brief: yesterday's leftovers, each with `Today / Kill / Reschedule`.
  - `Sun 03:00 IST` — regenerate the rolling memory summary.
- **Sleep gating** — between 00:00–08:30 IST, if you said "goodnight" last night, fires are silently marked missed.
- **Conversational queries** — free-text questions get classified and answered against your working memory ("have I checked LinkedIn today?" → "Not yet. Scheduled for 9:30, you snoozed once.").
- **`/wipe`** — wipes all reminders, fires, recaps, summaries, and chat history. Keeps your user record. Confirm-button gated. **For testing iteration.**
- **`/seed`** — loads reminders from `seeds/default.json`. Edit that file with your defaults.
- **`/health`** — quick scheduler/job status check.
- **Owner lockdown** via `OWNER_TELEGRAM_USER_ID` env var (silently rejects others). If unset, accepts anyone — dev only.
- **Persistence** — APScheduler with Postgres-backed `SQLAlchemyJobStore`. Survives restarts; pending nags + recurring jobs are recovered on boot.
- **Persona voice** — Gemini-generated fire/recap/query text with hardcoded fallbacks. System prompt has the few-shot examples baked in.
- **Logging** — structlog JSON. Every Telegram interaction and scheduler event is logged.
- **Health check** — `/healthz` returns 200 if scheduler is running and DB is reachable.

## Local setup (dev — polling)

### Prereqs

- Python 3.11+
- Postgres 14+ running locally
- [`uv`](https://github.com/astral-sh/uv)
- Telegram bot token from [@BotFather](https://t.me/BotFather)
- Gemini API key from [Google AI Studio](https://aistudio.google.com/app/apikey)

### Steps

```bash
# 1. Create the database
createdb prometheus

# 2. Configure env
cp .env.example .env
# Edit .env — set TELEGRAM_BOT_TOKEN, GEMINI_API_KEY, OWNER_TELEGRAM_USER_ID.
# (Find your Telegram id via DM to @userinfobot.)
# Leave WEBHOOK_URL/WEBHOOK_SECRET blank in dev. ENV=dev keeps polling.

# 3. Install deps
uv sync

# 4. Run migrations
uv run alembic upgrade head

# 5. Start the bot
uv run prometheus
```

DM your bot, send `/start`, reply with your name, then try `/r 21:30 once Test ping` or just type "remind me in 1 min to wave".

## Production deploy (Render)

### One-time setup

1. **Push the repo to GitHub.** Make sure `.env` is gitignored (it is).
2. **Render → New Blueprint** → point at the repo. `render.yaml` defines:
   - `prometheus-db` Postgres (Starter, Singapore, PG 16)
   - `prometheus` Web Service (Docker, Starter, Singapore)
3. Set the secret env vars in the Render dashboard:
   - `TELEGRAM_BOT_TOKEN`
   - `GEMINI_API_KEY`
   - `OWNER_TELEGRAM_USER_ID`
   - `WEBHOOK_URL` — leave empty for the first deploy; after the service has a URL like `https://prometheus.onrender.com`, set this and re-deploy. The bot sets the Telegram webhook on boot to `<WEBHOOK_URL>/webhook/<WEBHOOK_SECRET>`.
   - `WEBHOOK_SECRET` is auto-generated by Render the first time. Don't change it.
4. **DATABASE_URL** comes from the Postgres add-on automatically (Render injects `postgresql://…`; the app normalizes it to `postgresql+asyncpg://…`).
5. Migrations run automatically on each container start (`alembic upgrade head` is in the Dockerfile `CMD`).
6. Health check: Render polls `/healthz`. Returns 200 if scheduler is running and DB is reachable, 503 otherwise.

### Promoting from dev to prod

| Var | Dev | Prod |
|---|---|---|
| `ENV` | `dev` | `prod` |
| Mode | Long-polling | Webhook (own tornado server on `PORT`) |
| `DATABASE_URL` | Local Postgres | Render Postgres add-on |
| `WEBHOOK_URL` | (unused) | `https://prometheus.onrender.com` |
| `WEBHOOK_SECRET` | (unused) | auto-generated by Render |

### Tearing down for clean retesting

`/wipe` from Telegram clears all data **except** your user record:
- All `reminders`, `reminder_fires`
- All `daily_recaps`, `memory_summary`
- All `chat_messages`
- All scheduled jobs in APScheduler (reminder/nag/snooze; system cron jobs preserved)

Run it after each test session if you want a clean slate. The user row stays so you don't have to re-onboard.

For a true full reset (drop the DB), in dev:
```bash
uv run alembic downgrade base && uv run alembic upgrade head
```

## Manual test plan

Tap-through after deploying:

- [ ] `/start` → asks for name on first contact.
- [ ] Send any text → gets logged to chat_messages.
- [ ] `/r 09:30 weekdays Check LinkedIn perf` → confirms with id, list shows it.
- [ ] `/r in 1 min Test ping` → 1 min later, message arrives with 4 buttons.
- [ ] Tap Done → message buttons disappear, `Logged.` toast.
- [ ] `/r in 1 min Nag test` → don't tap → 10 min later first nag edits the message; another 10 min for nag 2; another 10 min for the escalated nag 3.
- [ ] `/r in 1 min Snooze test` → tap Snooze → "back in HH:MM IST"; 30 min later it fires again with snooze_count=1.
- [ ] Snooze 3 times → on the 4th fire, Snooze button is hidden.
- [ ] `/r in 1 min Note test` → Add Note → "Shoot." → type "blocked on review" → Done/Pending appear → tap one.
- [ ] Free-text "remind me to wind down at 11pm daily" → confirmation flow with Confirm/Edit/Cancel.
- [ ] Free-text low-confidence input → bot asks one clarifier; reply; if still low conf, commits with "going with this — /list to fix".
- [ ] Free-text query "have I checked linkedin today?" → bot answers from working memory.
- [ ] Restart bot mid-nag-cycle → nag resumes from now, no catch-up burst.
- [ ] `/wipe` → confirm → all reminders/fires/chat cleared, scheduler purged of reminder/nag/snooze jobs (system cron jobs intact).
- [ ] Wait until midnight IST → recap message arrives with sleep buttons.
- [ ] Tap "Yes, goodnight" → fires between 00:00–08:30 next morning are silently missed.
- [ ] At 10:30 IST → morning brief lists yesterday's leftovers with per-item buttons.

## Architecture invariants

- **All datetimes stored UTC, displayed IST.** `DateTime(timezone=True)` everywhere; `ZoneInfo("Asia/Kolkata")` for display.
- **Single asyncio process.** PTB + AsyncIOScheduler + (in prod) tornado all share one event loop.
- **Webhook in prod, polling in dev.** Switched by `ENV=prod`.
- **APScheduler jobs persist to Postgres.** On restart, recurring jobs and pending-fire nags are recovered.
- **Idempotent fire callbacks.** Tapping Done twice does the right thing.
- **Secrets via env vars only.** `.env` is gitignored.
- **Gemini failure is graceful.** Every Gemini call has a hardcoded fallback path; the bot never breaks because of an LLM outage.

## Known caveats

- `pending_parse` and `awaiting_note_for_fire` live in PTB's in-memory `chat_data`. If the process restarts mid-flow, you re-tap. Reminder firing state survives restarts (DB-backed); only the transient one-shot conversation flags don't.
- Snoozing reuses the `snooze:<fire_id>` job id, so the "Today" path from the morning brief reuses the same plumbing — slightly odd but harmless.
- The Gemini SDK call uses `temperature=0.1` for parser, `0.0` for intent, `0.3-0.5` for persona. Tweak in `llm/` if outputs feel off.
